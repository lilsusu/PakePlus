AI 短剧一站式服务平台

产品需求文档（PRD）— 统一托管 AI Key、积分消耗驱动、全自动短剧生产 + 画布编排 + 提示词工程

文档版本：v1.0.0
日期：2026-10-10
状态：Draft
架构：Laravel 12 + Python FastAPI
📋 文档说明

本 PRD 定义"AI 短剧一站式服务平台"的产品行为与业务决策，覆盖后台管理端、用户端、服务端、支付与积分系统、AI 平台 Key 管理、全自动工作台、画布工作台、画布共享社区、提示词工程中心共 13 个子系统。技术架构、数据库设计、API 文档见独立的 技术设计文档。

优先级标记： P0 必须上线   P1 首版后快速迭代   P2 远期规划

1背景与目标

1.1 背景与问题

短剧创作链条长——从大纲、剧本、分镜到参考图、视频生成、最终合并——每一步都依赖不同 AI 模型（文生文、文生图、图生视频、TTS、FFmpeg）。当前痛点：

  • Key 管理碎片化：创作者需自行购买和管理多家 AI 平台 API Key，成本高、密钥泄露风险大。
  • 流程割裂：大纲工具 → 剧本工具 → 绘图工具 → 视频工具之间需手动搬运中间产物，缺乏端到端自动化。
  • 提示词质量不可控：每个节点提示词依赖个人经验，无版本管理、无 A/B 测试、无质量反馈闭环。
  • 计费不透明：各模型计费方式不同（Token / 次数 / 时长 / 分辨率），用户无法预估总成本。

1.2 产品决策

平台统一托管所有 AI 平台 API Key，用户不直接接触 Key，通过积分消耗使用 AI 能力。后台为每个 AI 模型配置计费倍率和扣费规则，用户充值积分 → 预扣积分 → 任务执行 → 实际结算 → 失败退回。同时提供全自动工作台（端到端流水线）和画布工作台（自由编排节点），并通过提示词工程中心实现提示词的配置、优化、A/B 测试和版本管理。

1.3 可观察结果

  • 创作者可在单一平台内完成"剧名输入 → 最终 MP4 输出"的全流程，无需接触任何 API Key。
  • 每个节点运行前显示积分预估和预计耗时，运行后可评分、重生成、修改提示词重跑。
  • 后台可追踪每个 AI 模型的调用量、成本、毛利率，并对提示词进行 A/B 测试优化。
  • 支付回调验签、幂等、可对账、可退款；所有关键操作有审计日志。

2.3 P2 — 远期规划

  • 企业用户子账号与团队协作
  • 画布模板市场与创作者分成
  • 多语言/多地区部署
  • 开放 API 供第三方接入

2.4 明确排除

  • 平台不自建 AI 模型，只做 API Key 托管与调度。
  • 不提供短剧分发/播放平台，只负责生产环节。
  • 不直接处理用户银行卡支付（通过第三方支付渠道）。

3系统角色与权限

3.1 角色定义

角色职责权限边界
超级管理员平台全局管理所有模块读写，含系统配置与 Key 管理
运营日常运营管理用户/内容/画布/公告/优惠券，不含财务与 Key
财务资金与积分管理订单/退款/积分调整/财务统计，不可改 Key
客服用户支持用户详情只读、消息发送、积分调整建议
审核员内容审核作品/画布/提示词审核，不可编辑内容
提示词工程师提示词配置与优化提示词中心全部功能，含发布与回滚
普通用户使用 AI 能力用户端全部功能，积分消耗
创作者高级创作普通用户 + 画布发布/共享/模板
企业用户团队协作普通用户 + 子账号管理（P2）

3.2 权限模型

采用 RBAC（基于角色的访问控制），支持：

  • 角色 → 权限点：权限点粒度到"模块 + 操作"（如 ai-keys.read、ai-keys.write）。
  • 角色 → 菜单：控制后台侧边栏可见菜单。
  • 数据范围：支持全部数据 / 本人数据 / 本部门数据 三级控制。
  • 用户可多角色：一个用户可同时拥有多个角色，权限取并集。

4.1 核心用户旅程

注册/登录→ 充值积分→ 创建项目→ 加载默认提示词→ 全自动/画布工作台→ AI 任务执行→ 预扣→结算积分→ 导出 MP4

4.2 支付与积分流

选择套餐→ 创建订单→ 调起支付→ 回调验签→ 积分到账→ 订单完成

4.3 AI 任务生命周期

状态流转：待排队 → 预扣积分 → 执行中 → 生成中 → 后处理中 → 成功 / 失败 →（失败时）已退回；任意执行前状态可 → 已取消

4.4 共享业务对象

对象定义多角色协作场景
项目（Project）一部短剧的顶层容器，关联大纲/剧本/分镜/视频等全部产物用户创建、运营管理、审核员审核
积分钱包（Wallet）用户积分账户，含可用余额与冻结积分用户消耗、财务调整、系统结算
订单（Order）充值订单，关联支付渠道与积分到账用户支付、财务退款、系统回调
AI 任务（AiTask）一次 AI 调用记录，关联模型、积分、状态用户触发、Python 执行、系统结算
提示词模板（PromptTemplate）可复用的提示词定义，含变量与版本工程师编辑、用户覆盖、系统加载
画布（Canvas）节点编排图，含节点与连线用户创建、社区共享、运营审核

5功能需求

以下按后台管理端（5.1–5.12）和用户端（6.1–6.5）分模块展开。每个模块标注优先级。

5.1后台仪表盘 P0

FR-DASH-01 仪表盘概览

目的：管理员登录后首页展示核心运营指标，快速掌握平台健康度。

展示内容：

  • 用户指标：总用户数、今日新增、活跃用户、付费用户数
  • 收入指标：今日/本周/本月收入、充值总额、退款金额
  • 积分指标：积分消耗总量、冻结积分总量、积分退回率
  • AI 成本：各平台调用成本、Key 余额预警
  • 调用量：各模型调用次数、成功率、平均耗时

权限：超级管理员、运营、财务可查看；客服只看用户指标。

5.2用户管理 P0

FR-USR-01 用户列表与搜索

触发：管理员进入"用户管理"菜单。

功能：分页列表展示用户 ID、昵称、手机号、积分余额、累计消费、注册时间、状态。支持按手机号/昵称/ID 搜索，按状态/角色/注册时间筛选。

权限：超级管理员、运营、财务、客服可查（客服仅看基础信息）。

FR-USR-02 用户详情

展示：基础资料、积分钱包（余额+冻结+流水）、订单记录、AI 任务记录、作品列表、画布列表、消息通知、邀请关系树。

权限：超级管理员、运营、财务、客服（客服无积分调整权限）。

FR-USR-03 积分调整

触发：财务/超级管理员在用户详情页点击"积分调整"。

处理规则：

  • 必须填写调整类型（增加/扣减）、数量、原因。
  • 调整后实时更新钱包余额，记录积分流水（类型=调整）。
  • 扣减时校验余额充足，不足则提示并阻止。
  • 记录审计日志：操作人、操作时间、调整前后值、原因。

异常：余额不足时不允许扣减；网络超时重试需幂等（同一调整请求 ID 不重复执行）。

FR-USR-04 封禁/解封

处理规则：封禁时填写原因和时长（永久/临时），封禁后用户无法登录和消费；进行中的 AI 任务自动取消并退回积分。解封恢复登录能力。

审计：记录操作人、时间、原因，用户可看到封禁原因。

FR-USR-05 会员与实名

会员：可设置会员等级、有效期、专属积分倍率。实名：记录实名认证状态（未认证/审核中/已认证/已拒绝），支持上传证件图片人工审核。

5.3权限管理（RBAC）P0

FR-RBAC-01 角色管理

功能：角色 CRUD，每个角色配置：名称、描述、权限点集合、可见菜单、数据范围（全部/本人/本部门）。

处理规则：系统预置 9 种角色不可删除但可调整权限点。新建角色需指定权限点和菜单。

FR-RBAC-02 权限点管理

定义：权限点 = 模块名 + 操作类型，如 users.read、users.write、ai-keys.write。支持按模块分组展示。

FR-RBAC-03 用户角色分配

处理规则：一个用户可分配多个角色，权限取并集。分配/移除角色记录审计日志。

5.4支付管理 P0

FR-PAY-01 支付渠道配置

功能：插件化管理微信支付、支付宝、Stripe、PayPal、易支付。每个渠道配置：应用 ID、密钥（加密存储）、回调地址、启用状态、环境（沙盒/生产）。

安全：密钥 AES-256 加密存储，后台脱敏显示（仅显示前 4 后 4），日志不记录完整密钥。

FR-PAY-02 套餐管理

功能：充值套餐 CRUD。字段：名称、价格（元）、基础积分、赠送积分、首充标识、有效期、会员等级关联、启用状态。支持排序和限时上下架。

FR-PAY-03 订单管理

功能：订单列表展示订单号、用户、套餐、金额、渠道、状态（待支付/已支付/已到账/已退款/已关闭/失败）、创建时间、支付时间。支持搜索、筛选、导出。

权限：超级管理员、财务可操作退款。

FR-PAY-04 退款

触发：财务在订单详情页点击"退款"。

处理规则：

  • 校验订单状态为"已到账"且未退款。
  • 校验用户积分余额 ≥ 退款积分（已消费的积分不可退）。
  • 调用支付渠道退款接口，记录退款单。
  • 退款成功后扣减用户积分，更新订单状态为"已退款"。
  • 退款幂等：同一退款请求不重复执行。

审计：记录操作人、退款金额、退款积分、退款原因。

FR-PAY-05 回调日志与对账

功能：展示所有支付回调原始报文、验签结果、处理状态、处理时间。支持按渠道/日期筛选。对账功能：比对平台订单与渠道账单，标记差异。

5.5积分管理 P0

FR-PTS-01 积分流水

功能：全局积分流水列表，字段：流水号、用户、类型（收入/支出/冻结/退回/调整）、关联对象（订单号/任务号）、积分数、变动前后余额、时间。支持搜索和筛选。

FR-PTS-02 冻结积分管理

功能：查看所有冻结积分记录，关联 AI 任务。任务成功时冻结→结算扣除；任务失败时冻结→退回可用。

FR-PTS-03 优惠券 P1

功能：优惠券 CRUD：类型（满减/折扣/赠送积分）、面值、门槛、有效期、发放范围（全量/指定用户/首充）。用户充值时可抵扣。

FR-PTS-04 兑换码 P1

功能：批量生成兑换码（积分面值、有效期、使用限制、批次号）。用户端输入兑换码核销后积分到账。核销幂等，一码一用。

FR-PTS-05 积分过期规则

处理规则：后台可配置积分过期策略：是否启用、过期周期（如 365 天）、过期提醒（到期前 7/3/1 天通知）。过期积分自动清零并记录流水。

5.6AI 平台配置 P0

FR-AI-01 供应商管理

功能：供应商 CRUD：名称、标识（openai/anthropic/gemini/deepseek 等）、默认端点、代理地址、超时、重试次数、熔断阈值、启用状态。

FR-AI-02 模型管理

功能：模型 CRUD：所属供应商、模型标识、能力类型（文生文/文生图/图生视频/TTS/视频合成）、计费方式（Token/次数/时长/分辨率）、计费倍率、积分单价、并发限制、限流（QPS）、启用状态。

计费规则：积分消耗 = 基础成本 × 计费倍率。基础成本按计费方式计算（Token 数 × Token 单价 / 调用次数 × 次单价 / 视频时长 × 时长单价）。

FR-AI-03 Key 池管理

功能：Key 池 CRUD：所属供应商/模型、Key 值（AES-256 加密存储）、权重、状态（正常/限流/故障/禁用）、当前余额、上次余额查询时间。

Key 调度策略：

  • 轮询：按权重轮询分配 Key。
  • 故障转移：Key 报错后自动切换到下一个可用 Key，标记故障。
  • 额度监控：定时查询 Key 余额，低于阈值告警。
  • 异常告警：Key 连续失败超阈值时自动禁用并通知管理员。

安全：后台脱敏显示（前 4 后 4），日志不记录完整 Key。只有超级管理员可查看完整 Key。

FR-AI-04 成本统计

功能：按供应商/模型/日期维度展示调用次数、成功率、实际成本（元）、积分消耗、毛利率。支持导出报表。

5.7提示词工程中心 P0

提示词工程中心是本平台的核心差异化能力，用于配置、优化、测试、发布和管理全自动工作台各节点的 AI 提示词。

5.7.1 提示词分类

分类用途优先级
系统提示词平台级基础指令，如安全合规约束P0
节点提示词绑定到全自动工作台各节点（大纲/剧本/表格/参考图/分镜图/视频/合并）P0
类型提示词按剧集类型预设（古装/都市/甜宠/悬疑/玄幻等）P0
风格提示词按视觉风格预设（写实/电影感/国风/动漫/3D 等）P0
负向提示词排除不想要的元素P0
参数预设模型参数默认值（temperature/seed/steps 等）P1
结构化输出提示词强制 JSON/表格格式输出P0
审核提示词内容审核专用提示词P1
重写提示词基于已有内容进行改写优化P1

FR-PMT-01 提示词模板 CRUD

功能：提示词模板的创建、编辑、预览、删除、复制、导入导出 JSON。

模板字段：

  • 名称、分类、描述
  • 提示词内容（支持变量占位符）
  • 变量定义：变量名、类型、必填、默认值、校验规则
  • 适用模型、适用节点
  • 状态：草稿/测试中/已发布/已下线

变量系统：支持 {{genre}}、{{style}}、{{audience}}、{{outline}}、{{characters}}、{{episode}}、{{duration}}、{{ratio}}、{{platform}} 等变量。支持默认值、必填校验、变量预览。

FR-PMT-02 版本管理

处理规则：

  • 每次编辑保存生成新版本，保留历史版本。
  • 版本状态：草稿 → 测试中 → 已发布 → 已下线。
  • 支持版本间差异对比（diff 视图）。
  • 已发布版本可回滚到历史版本。
  • 记录每个版本的修改人、修改时间、修改原因。

FR-PMT-03 类型预设

功能：管理剧集类型预设：古装、都市、甜宠、逆袭、悬疑、玄幻、科幻、战神、萌宝、婆媳、职场等。每种类型配置默认的大纲、剧本、分镜、参考图、视频、负向提示词、节奏参数。

触发：用户创建项目选择类型时，系统加载对应类型预设作为默认提示词。

FR-PMT-04 风格预设

功能：管理视觉风格预设：写实、电影感、国风、动漫、3D、赛博、水墨、港风、韩系、日系、复古等。每种风格配置画面提示词、镜头语言、色彩、光影、构图、参考图风格、视频运镜、负向提示词。

FR-PMT-05 节点绑定

功能：将提示词模板绑定到全自动工作台各节点。绑定维度：

工作流节点 + 内容类型 + 风格 + AI 平台 + 模型 + 语言 + 平台渠道 + 画面比例 + 时长 + 受众
示例：大纲节点 + 古装 + 国风 + 即梦 + 抖音 + 9:16

配置项：优先级、启用状态、灰度比例、A/B 测试分组。同一节点可绑定多套提示词，按优先级和灰度比例选择。

FR-PMT-06 AI 辅助优化 P1

流程：

  1. 选择优化目标：提升质量 / 降低成本 / 提高合规率 / 增强风格一致性 / 减少重生成。
  2. 系统调用 AI 模型改写提示词，生成候选版本。
  3. 展示候选与原版差异、测试生成结果、积分消耗、耗时、质量评分。
  4. 人工评分后可"采纳为默认"或"另存为个人模板"。

优化依据：生成结果评分、用户反馈、重生成率、失败率、采纳率、积分消耗、耗时、合规率。

FR-PMT-07 A/B 测试 P1

功能：同一节点绑定 A/B 两套提示词，配置流量比例（如 50/50）、测试时间范围、目标指标（成功率/质量评分/成本/耗时）。系统自动收集数据并推荐胜出版本，支持一键发布。

FR-PMT-08 反馈分析 P1

功能：收集用户对生成结果的评分、重生成、删除、导出、采纳行为。统计成功率、重生成率、投诉率、合规率、平均积分消耗。反馈数据反哺默认提示词优化。

FR-PMT-09 权限与审计

权限：提示词工程师可编辑/发布/回滚；运营只读或提交建议；超级管理员全部权限。

锁定规则：后台可锁定系统提示词，锁定后用户端不可修改该部分，只能修改用户提示词部分。

审计：所有提示词的创建、修改、发布、回滚、删除操作记录审计日志，含操作人、时间、变更内容。

7共享规则与异常

7.1 支付安全规则

规则定义
验签所有支付回调必须验签，验签失败拒绝处理
幂等同一订单号 + 回调报文哈希不重复处理；重复回调返回已处理状态
防篡改订单金额在创建时锁定，回调金额与订单金额不一致时拒绝
防重放回调报文含时间戳和 nonce，超时（如 5 分钟）拒绝，nonce 不可重复
防刷积分异常频率充值触发风控（人工审核）；新用户首充延迟到账（T+1 或人工确认）
回调重试回调处理失败自动重试（指数退避，最多 5 次），仍失败则人工处理
对账每日自动比对平台订单与渠道账单，差异标记并通知财务
退款退款校验积分余额，退款幂等，退款后扣减积分并更新订单

7.2 积分计费规则

规则定义
计费方式按模型配置：Token 计费 / 次数计费 / 时长计费 / 分辨率计费
积分单价每个模型配置积分单价（基础成本 × 计费倍率）
预扣任务创建时按预估上限预扣积分到冻结
结算任务成功后按实际消耗结算，多扣的冻结积分退回可用
失败退回任务失败/取消/超时，冻结积分全额退回可用
余额校验预扣前校验可用积分 ≥ 预估消耗，不足则阻止任务创建
流水记录所有积分变动记录流水（收入/支出/冻结/退回/调整），含关联对象
过期按后台配置过期策略，到期自动清零并记录

7.3 任务生命周期规则

规则定义
入队所有 AI 任务进入 Redis 队列，Python Worker 拉取执行
预扣入队前预扣积分，预扣失败不入队
进度推送Python Worker 通过 Webhook 回调 Laravel，Laravel 通过 WebSocket/SSE 推送前端
失败重试按模型配置重试次数和间隔，超限标记失败
超时取消超过配置超时时间自动取消，退回积分
优先级支持任务优先级（如会员优先），高优先级先出队
并发控制按模型配置并发限制，超限排队等待
任务日志记录任务全生命周期日志（入队/执行/进度/完成/失败/退回）
成本记录记录每个任务的实际 AI 调用成本（元）和积分消耗

7.4 合规与审计规则

规则定义
内容审核AI 生成内容自动过审（敏感词 + 图像审核），命中标记待人工审核
版权提示生成内容展示版权声明，用户确认使用
肖像权提示涉及人物图像时提示肖像权风险
未成年人保护内容分级标识，不适内容限制访问
深度合成标识AI 生成视频和图片添加深度合成标识（水印/元数据）
提示词注入防护用户输入的提示词经过净化，防止注入攻击
敏感词过滤提示词和生成内容过敏感词库
Key 安全所有 API Key AES-256 加密存储，后台脱敏显示，日志不记录完整 Key
审计日志所有关键操作（支付/积分调整/Key 管理/提示词变更/用户封禁/内容审核）记录审计日志
系统提示词锁定后台可锁定系统提示词，用户只能修改用户提示词部分

7.5 通信机制约束

  • Laravel 创建 AI 任务记录 → 推入 Redis 队列 → Python Worker 拉取执行 → 执行完成后 POST 回调 Laravel Webhook → Laravel 更新状态、结算积分、推送进度。
  • Python 不直接操作 MySQL，所有数据读写通过 Laravel API。
  • Laravel 不阻塞等待 Python，任务全程异步。
  • 积分扣费由 Laravel 统一管理（预扣 → 结算 → 失败退回）。
  • 所有写操作幂等，支付回调验签，任务可重试。
